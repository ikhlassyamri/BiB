- **`/artikel/`** — **rumah semua artikel umum** + halaman katalog (`index.html` = joinbib.id/artikel). Artikel baru non-clipper ditaruh di sini (`/artikel/<slug>.html`, URL extensionless).
  - **Katalog otomatis:** daftar artikel diatur lewat array `ARTIKEL` di dalam `artikel/index.html` (ada blok komentar "TAMBAH ARTIKEL BARU DI SINI"). Tiap artikel punya `niche` (topik: AI/Clipper/Keuangan/Bisnis — boleh >1) + `jenis` (Panduan/Tutorial/Edukasi/Rekomendasi). **Tombol filter dibuat otomatis dari data**, jadi topik/jenis baru langsung muncul sendiri tanpa ngoding.
  - **Wajib tiap nambah artikel:** (1) taruh file di `/artikel/`, (2) tambah 1 objek ke array `ARTIKEL`, (3) tambah link ke `<noscript>` di file yang sama, (4) update `sitemap.xml`.
  - _Artikel clipper TIDAK dipindah_ — tetap di `/clipper/`, tapi ikut tampil di katalog ini.
  - **Warna:** halaman ini sengaja **monokrom (aksen putih, var `--ac`)**, bukan hijau neon — supaya jadi wadah netral: warna tiap sub-brand (hijau IkhlasClip, dst) yang menonjol lewat thumbnail, dan tidak bentrok kalau nanti ada sub-brand warna baru.
  - **Notifikasi:** 2 kartu langganan. (1) Saluran WhatsApp — selalu aktif. (2) Push browser via OneSignal — baru muncul setelah `ONESIGNAL_APP_ID` di `artikel/index.html` diisi; selama masih `GANTI-INI` kartunya sengaja disembunyikan. Service worker-nya `/OneSignalSDKWorker.js` di root (jangan dipindah).
- **`/.github/workflows/`** — otomatisasi GitHub Actions. `notifikasi-artikel-baru.yml`: tiap ada file HTML **baru** masuk `/artikel/` dan ke-push ke `main`, judul + ringkasan + canonical-nya dibaca lalu dikirim jadi push OneSignal otomatis. Mengedit artikel lama tidak memicu apa pun. Tulis `[tanpa-notif]` di pesan commit untuk melewati. Butuh secret repo `ONESIGNAL_REST_API_KEY` (REST API Key OneSignal — **rahasia**, jangan pernah ditulis di kode). **Tidak bisa mengirim dobel** (Agu 2026: dua artikel pernah terkirim dua kali ke 85 pelanggan, berjarak 1 detik — dua run balapan): `concurrency` membuat run berikutnya menunggu, dan `external_id` = `uuid5(NAMESPACE_URL, alamat kanonik)` membuat OneSignal menolak kiriman kedua dengan kunci yang sama. Kuncinya DITURUNKAN dari alamat, bukan diacak — acak berarti tiap run punya kunci baru dan tidak menahan apa pun. HTTP 409 dari OneSignal karena itu dibaca sebagai **sukses** ("sudah pernah dikirim"), bukan galat. Konsekuensinya: satu alamat artikel = satu notifikasi selamanya; mengirim ulang alamat yang sama harus lewat dasbor OneSignal.
- **`/.github/workflows/periksa-notifikasi.yml`** — alat DIAGNOSA notifikasi (jalankan manual dari tab Actions). GET saja ke OneSignal, tidak pernah POST, jadi tidak menghasilkan notifikasi ke siapa pun — kecuali kolom `osid` diisi, yang mengirim SATU notifikasi uji ke satu langganan itu saja. Dibuat Agu 2026 karena log pengirim mencetak "TERKIRIM" berbekal `id` dari OneSignal, padahal `id` cuma bukti kirimannya DIBUAT. Yang menjawab "sampai atau tidak" ada di sisi OneSignal: `players`, `messageable_players`, `successful` tiap kiriman, dan `invalid_identifier` tiap langganan. **Temuan pertamanya:** push artikel SEHAT (84-90 perangkat menerima tiap kiriman), tapi **80 dari 165 langganan alamat push-nya MATI** (`invalid_identifier`) — perangkat yang ada di golongan itu tidak menerima apa pun sampai ia BERLANGGANAN ULANG, dan tidak ada kode di sisi kita yang bisa memperbaikinya. Catatan jebakan: versi API yang menjawab `/players` tidak lagi mengisi `notification_types` (semuanya `None`) — jangan dibaca sebagai "nol pelanggan".

- **`/baca/`** — **halaman baca gratis e-book** (Agu 2026). Tiap buku Trilogi AI punya satu halaman: daftar isi PENUH (judul bab terkunci ikut tampil — itu copy penjualan terbaiknya, dan gratis), pendahuluan utuh, lalu Bab 1 dipotong di tengah pada subjudul yang menjanjikan sesuatu. Sekitar **10% buku** — keputusan pemilik, Agu 2026: "ini bacaan loh, bukan komik, komik aja kayak Webtoon cuman ngasih gratis beberapa halaman". **DUA ATURAN YANG TIDAK BOLEH DILANGGAR:** (1) isi terkunci TIDAK PERNAH ikut dikirim ke halaman — di situs statis, buram lewat CSS itu hiasan, bukan gembok (view-source, mode Baca, atau matikan CSS = seluruh bab bocor); (2) cuplikan buramnya potongan secukupnya dan buramnya **DIBAKAR ke dalam berkas JPG** — blur CSS bisa dilepas lewat DevTools, gambar buram tidak, dan satu bab penuh yang dirender jadi gambar tetap terbaca kalau di-zoom. **Yang dibaca pengunjung adalah HALAMAN PDF ASLINYA** (keputusan pemilik, Agu 2026: "saya ga pengen ditulis oleh kamu, tapi benar2 isi ebooknya disana"), dirender jadi gambar dan dibalik seperti buku sungguhan — sampul, halaman judul, daftar isi, pendahuluan, lalu Bab 1 sampai mentok. Balik halamannya `rotateY` 3D murni CSS: ketuk sisi kanan/kiri lembar, geser, atau tombol panah. Lembar dimuat bertiga (yang dibaca plus tetangganya), bukan dua belas sekaligus. Lembar TERAKHIR separuh bawahnya diburamkan tepat di bawah subjudul potong — batasnya dicari dari posisi subjudul di PDF, bukan angka mati — lalu pop-up gemboknya muncul.
